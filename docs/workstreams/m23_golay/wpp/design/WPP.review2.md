## 2. What I reproduced

### 2.1 Group and generation theorem (GAP 4.12.1, `review2/rv2_rows.g`)

- `Group(g1, g2)` from the owner's `m23.py` cycles has order 10,200,960. It is `M(23)`, and
  `g1 g2 g3 = ()`.
- `MaximalSubgroupClassReps` of that group has orders 443520, 40320, 40320, 20160, 7920, 5760 and
  253. Only the last is transitive. So the theorem of 5.2 holds as stated.
- On the four rational sample rows I also compared `IsTransitive` with `Size = |G|` for every
  survivor: 0 disagreements out of 22,849 pairs. The criterion agrees with GAP's group order.

### 2.2 Class identification

- The proof of 3.2 is sound. It has three steps: a class function, a different value on `x` and
  `x^-1`, and a count. One more argument makes the 14A convention automatic. Over `F_2`,
  `tr(A^2) = tr(A)^2 = tr(A)`. So the class whose squares lie in 7A (trace 1) also has trace 1,
  with no separate measurement needed. The same identity shows the trace naming fits GAP's power
  maps `2` on 7, 15 and 23, because 2 is a square mod 7, 15 and 23.
- `full_census` was rerun. All 10,200,960 labels give GAP's 17 class sizes. Sign equals trace on
  all 887,040 elements of order 23. The 17 centralizers by scan equal GAP's.
- `full_family_11` was rerun. The fast 11 test equals the family test on all 1,854,720 elements
  of order 11 (927,360 in 11A).
- Matching with GAP's names. `AutomorphismsOfTable(CharacterTable("M23"))` has order 16. It equals
  the group generated by `PermList(PowerMap(t, k))` for the primes `k < 2000` prime to the
  exponent 212520 (`review2/rv2_aut.g`: `equal true`). So the table automorphisms are exactly the
  Galois maps `g -> g^k`, and every structure constant is invariant under them. The revised
  `debug_fast` checks GAP's power maps 2, 3, 5, 7, 11, 23 and -1 exactly on RustMath's classes. A
  naming that fits all power maps and sizes is GAP's naming up to a table automorphism. That is
  the documented ambiguity, and nothing more. (Review 1 also matched 3,017 labelled elements
  through GAP's fusion.)
- Misclassification hunt. Inside M23 none is possible: the census gives exact class sizes, so by
  3.2 each split type is exactly the two classes. Outside M23 the rule misclassifies, as
  documented (8.3, 9). Examples: a `2^8 1^7` involution not in M23 is called 2A, and a 22-cycle is
  called 11B by the fast path. `class_of_checked` sifts first and refuses them. The cyclic sign of
  a 23-cycle outside M23 gives `InvariantFailed`.

### 2.5 Generation

The criterion is cited correctly (ATLAS p. 71, the M23 entry). It applies to every one of the 57

### 2.6 Real structure

- Conjugate pairs: if `h a h^-1 = a^-1` and `h b h^-1 = a b`, then `h^2` centralizes `<a, b>`, so
  `h` is an involution. It is unique, and `a = c b c b^-1`. Then `a b = c b c` lies in D
  automatically. The formula is right, and GAP agrees on 6 rows.
- Three real points: I checked the derivation of 5.3. With the base point between `t1` and `t2`,
  conjugation fixes both segments and reverses the small circles, so `kappa_*` inverts
  `gamma_1` and `gamma_2`. The conjugate cover has monodromy `phi o kappa_*`. The third branch
  cycle is fixed up to conjugacy, since `ab` and `ba` are conjugate. The decomposition `a = c u`
  with `u^2 = 1` is a bijection onto the fixed generating pairs, because `c` is unique. The
  argument is complete. The label `TrustedResult::ConjugationThreeRealPoints` is honest, since the
  classical sources were not read.
- `full_c_23a_23b` was rerun. The six classes match `passports_C_23A_23B.json` entry by entry,
  including `representatives_g1`. `dim W = g`, `dim W^dual = g` and `dim Jac[2] = 2g` hold on all
  6,127 triples, and `g + r - 1` holds on every real cover.

### 2.7 Dictionaries

- HJLPPZ rows 1..7 -> `[5, 4, 0, 2, 1, 3, 6]`;
- Janik rows 0..6 -> `[3, 5, 1, 6, 2, 4, 0]`;

All three equal `group_facts.json` (`hjlppz_file_row`, `janik_orbit`, `lelay_id`), and all three
are bijective.

## 3. Minor items (for the implementation)

- **n1. Validate a `ClassVector` passed by the caller.** `ClassVector` has public fields, and
  `count_class_vector` takes any value. The prototype's conjugate-pair count reads only
  `classes[0]` and `classes[1]` and assumes `classes[2] = classes[1]^-1`. So
  `ConjugatePair [3A, 7A, 7A]` would return the counts of `(3A, 7A, 7B)` under the wrong name.
  `[7A, 3A, 3A]` would apply the conjugate-pair real formula to a vector it does not describe.
  `NotRationalVector` exists, but its condition is not stated. Required change: specify the
  checks and test them in `degenerate_cases`. `Rational` needs three rational classes.
  `ConjugatePair` needs `classes[0]` rational, `classes[1]` not rational, and
  `classes[2] == classes[1].inverse()`. Anything else is an `Err`.
- **n2. `structure_count` is named in 5.2 but missing from the API.** Section 5.2 says survivors
  and `n` "are still returned by `structure_count`" when the generation criterion does not apply.
  Section 8.5 has no such function, and `count_class_vector` then returns only the `Err`.
  Required change: add `structure_count(..) -> Result<{survivors, n, centralizer_order, b_class,
  a_class}, ThreePointError>` to 8.5, or delete the sentence.
- **n3. T-215 residue: common keys.** With sizes on neither side, `try_inner_product` keeps the
  old mean over the *common* keys. Two characters with different key sets still give a plausible
  wrong value. `ClassFunction::inner_product` likewise skips keys missing on the other side.
  Required change: refuse different key sets. That means `Err(CharacterError::KeyMismatch)` when
  neither side has sizes, and `None` for `ClassFunction`. Add one test for each. The existing
  tests use equal key sets, so no assertion changes.
- **n4. `structure_constant` is not MAGMA's `StructureConstant`.** The ch. 91 digest
  (`Chapter_91_Characters_of_Finite_Groups.md:163`) defines `StructureConstant(G, i, j, k)` as the
  class-algebra coefficient `a_ijk`. The design's `n` is the normalized count of the HANDOFF.
  Check on `(2A,23A,23B)`: `a = 161`, `n = 161/23 = 7`. Required change: state the relation in
  the doc comment, `n(C1, C2, C3) = a_{C1, C2, C3^-1} / |C_G(c3)|`, or rename the method (for
  example `normalized_structure_constant`). That keeps the MAGMA tracker mapping honest.
- **n5. Small gaps in what is checked or recorded.**
  - The revised `debug_fast` does not check `permutation_character_23` or `orders` against
    RustMath's classes. Only the first prototype's release test checked the permutation
    character. `class_data_match_gap` (10.1) lists both, so implement both; they are cheap.
  - Record the debug peak memory the brief asks for: 12 MB per debug test, measured here.
  - State "zero `unsafe`" in Section 8.
  - Optionally, give the one-line proof `tr(x^2) = tr(x)` over `F_2` in 3.3 (Section 2.2 above).
