# C57 design review 1 (independent, adversarial)

Date: 2026-11-20. Reviewed: `design/C57.md` (all sections; it has no Revision section yet) and
`design/proto/`. Scratch for this review: `design/review1/` (scripts and outputs named below).
Nothing in the design, the prototype or any repository was edited. The owner's repository was
read with `git show` and `git archive e0d25b8` into `review1/owner_tree/` (no worktree; removed

## 0. Verdict

**Approve.** No blockers. The mathematics is right, and every decided value I recomputed by an
independent method agrees with the design. Ten minor items follow (Section 3). They are
specification gaps and test-plan additions; none changes a number in the design.

## 1. What I checked, and how

### 1.1 The proofs, read from first principles

- Lemma A (rank bound). Correct. `T/g(F)T` has order `2^v` and `d` cyclic summands, and
  `d = dim ker gbar(F)` on `J`; `v >= d`. Only `Res(P, g) != 0` and the Tate module structure are
  used. The twisted bound needs no twist theory: it is Lemma A with `g = x^k + 1`, and
  `ker(F^k + 1) = ker(F^k - 1)` on `J`.
- Lemma B, C (kernel dimension), D (order). Correct. Also checked numerically (1.2).
- Lemma E (only `k | N_max`). Correct in both cases. For `s <= s_max`, `kt = 2^s gcd(k', S)`
  divides `N_max`, gives the same `r_k` for every type, and `x^kt + 1 | x^k + 1` because `k / kt`
  is odd, so `Res(P, x^kt + 1) | Res(P, x^k + 1)` (the cofactor has integer coefficients). For
  `s > s_max` the bound is the same for every type.
- S0, S1. Correct (adjoint of `F` is `F^-1`; `f(F^-1) = F^-d f*(F)`).
- S2 in characteristic 2. I checked each step of the proof: the adjoint `N* = u^-1 N`, the
  symmetry and (for odd `j`) the alternating property of `b_j`, the radical
  `K_{j-1} + N K_{j+1}` (modular law), and the block count. The proof is complete.
- Lemma F and the use of Green/Klein. Correct, including the case `f != f*`
  (`W_f = Ann(W_{f*})`, quotient of `f`-type `mu_{f*}`). Only "a submodule of type `mu` with
  quotient `nu` exists implies `c != 0`" is used, which is the direction Macdonald II (4.3)
  gives.
- 2.7 (the rule of REQUESTS 1.2 is the case `k = 1`) and the remark `P(1) = P(-1) mod 4` when
  `(x+1)^2 | Pbar`. Correct.

### 1.4 A general fact the design can use

S1 and S2 never change the set of possible orders, for any set of bounds. Proof: every bound
`r_k` is monotone along dominance (`sum_i min(c, lambda_i)` is the sum of the first `c` parts of
the conjugate partition, which can only decrease when `lambda` moves up in dominance). Given a
candidate without S1, S2, replace each `lambda_f` (and `lambda_{f*}`, using the larger of the two
exponents) by the capped partition `(2^c, ..., 2^c, r)`, `c = c(max part)`. It dominates the
original, so it passes every bound; it has the same `2^c`, so the same order; for `x + 1` the
multiplicity is even (`J_{x+1}` is symplectic), so `r` is even and S2 holds. Hence the order
decision and the reason (a set of bounds) never depend on S1, S2. The design observes this only
on the 54 rows and on the hyperelliptic set (2.4, 3.5); with the lemma the "reason = bounds only"
of 2.6 is justified in general (item m9).

## 2. Things that look wrong but are fine

- The design adds the twisted bounds `x^k + 1`, which C-5 did not ask for. They are sound
  (Lemma A), and the decisions they give (X 109, L (41, 8), L (89, 69)) are confirmed in 1.3.
  4.4 names them as twist bounds, so the report to the owner is clear.
- The 8-letter cycle type is a table lookup (GAP and the owner agree), while the 15-point type is
  computed. The design says so in 7 and 13. That is honest and enough for "decide how much".
- `status` follows `zeta_X.json` (`"ok"`, `"refused"`), and RustMath's status goes to
  `rustmath_status`. The owner's scripts do not read `status` (see m4 for the note to the owner).

## 3. Minor items (required changes)

**m1. `two_torsion_frobenius_order` on the other errors (API).** 5.2 and 5.4 say it "never
returns an error" and give the fallback only for `TooManyCandidates` and `TooLarge`. For
`EvenCharacteristic` the natural fallback ("the bound of P mod 2 alone, as today") is a facade:
for `2 | q`, `P mod 2` is not the characteristic polynomial on `Jac[2]` (today's code even treats
the factor `x` as having order 1). For `Inconsistent` nothing is said. A zero resultant
(`Res(P, x^k -+ 1) = 0`, possible for a synthetic `P` from `from_coefficients`, which need not be
Weil) would ask for `v_2(0)`. Required: state the behaviour of each case. For example: panic with
a documented message for `q` even; `Inconsistent` returned by the analysis and, in
`two_torsion_frobenius_order`, a documented panic or the old `Unresolved` bound with a doc note;
a zero resultant gives no bound (skipped, recorded) or `Inconsistent`, never `v_2(0)`. In the M23
layer an `Err` prints the error in the order column and writes `jac2: {"error": ...}`; a row with
`weil = false` gets `order_status: "not applicable (P is not a Weil polynomial)"`.

**m2. What `W_status: "Decided"` means (JSON, text).** 8.2 says "Decided when one W type". With
two `Q` candidates (17, 73, 127 and every `(x+1)^2(x^3+x+1)(x^3+x^2+1)` row) the W list has two
entries with the same `mu`, so the class of `F` on `W` stays open (two classes of order 7, F-7),
while the type at 1 and the cycle types are decided. REQUESTS 1.2 bolds the class only where it is
decided (43, 89, 103, 113). Required: define separate statuses, for example
`W_type_eigenvalue_1_status` (one `mu_{x+1}` over all entries) and `W_cycle_types_status` (one
pair of cycle types), and say that `Q` versus `Q^rev` is not decided. Use the same words in the
text columns.

**m3. Tests of the symplectic constraints (test plan 9.1, 9.2).** `symplectic_filter` checks only
that some types are excluded, so it cannot catch a constraint applied too widely (a false
constraint gives a wrong `Decided`). S1 has no test where it matters (`f != f*` with `e_f >= 2`
needs genus 6). The hyperelliptic family is permutation modules only. Required: (a) a test with
the class representatives of `Sp(6,2)` and `Sp(8,2)` from GAP as a fixture (`review1/spclasses.g`
makes them in 5 s; 20 KB): every realized type passes the S1/S2 filter (expose the filter as a
`pub(crate)` function or test it in the module), and every stable Lagrangian's type is accepted
by the LR rule of `lagrangian_types` (2295 Lagrangians; enumeration is cheap); (b) an S1 unit
test on the filter for `(x^3+x+1)^2 (x^3+x^2+1)^2` (types tied; the type of `A + A^-T` on a
hyperbolic space is kept). This also gives `c5_all_rows` a reference that is independent of the
prototype (the class table with `r_k` by rank, as in `review1/rowcheck.py`).

**m4. The replaced file's keys (8.3, report to the owner).** In `rustmath_wpf_tables.json`
(`acea928`) `status` was RustMath's status (`"Decided: Nodal (62 nodes)"`); in the new file it is
`"ok"`/`"refused"`. The old key `two_torsion_order` is dropped, and the old file held `X` and `L`
in one object, while a run writes one cover. No owner script is affected. Required: say all three
in 8.3 and in the report, and give the one-line way to combine the X and L files if the owner
wants one file.

**m5. The mock is not in the 8.2 schema (8.4).** `proto/mock_X.json` has `format`
`"rustmath-m23-zeta-tables/1"` (8.1 says `"rustmath-m23-zeta/1"`), `jac2.reason` as a list of
bound names that kill some candidate (`["x^1+1", "x^1-1", "x^2+1", "x^4+1"]` at 109, where the
minimal decisive set of 2.6 is the single twisted bound at `k = 4`), `W_class` and
`W_type_eigenvalue_1` instead of `W`, no `decisive_bounds`, and `certificate.delta = 63` at the
`A_2` rows 13, 31, 41, 73 (the owner has 62; an `A_2` point has delta 1). The scripts read only the
legacy keys, so the result of 8.4 stands. Required: reword 8.4 ("a mock with the legacy keys") or
regenerate the mock from the 8.2 schema.

**m6. The JSON key test misses non-nodal rows (9.3).** `json_rows_carry_the_owners_keys` uses
X 7, 11 (62 nodes) and 23 (refused), so `certificate.delta` and the labels of `A_2`/`A_3` rows
are never compared with the owner's. Required: add X 5 (`A_3`, delta 62) or X 13 (`A_2`,
delta 62); both are cheap in debug.

**m7. Provenance (8.1).** `rustmath_commit` is read by `git rev-parse` at run time; the binary
may have been built from another tree (F9_impl.md Section 3 records exactly that). Required:
name the key for what it is (for example `rustmath_commit_at_run`, with `rustmath_tree_clean`),
or compare the executable's modification time with the commit time and say so. Say that
`command` is reconstructed and `argv` is exact.

**m8. A dangling reference (2.6, 4).** "Lemma 9.1" means the owner's paper (the F-9
certificate), but C57's own Section 9.1 is the unit tests. Required: write "Lemma 9.1 of the
owner's paper (F-9)".

**m9. State the lemma of 1.4 (2.4, 2.6).** The reason is a set of bounds only; that is complete
because S1, S2 never change the set of orders (proof in 1.4). Required: add the lemma and its
proof, and note that the minimal decisive set can be computed without S1, S2.

**m10. Small API points (5.1, 5.3).** `TooManyCandidates { count: u128 }`: the product of the
partition counts overflows `u128` for large genus; saturate. An empty result of
`lagrangian_types` on a row with a `Q` contradicts H_W: report it (an error or a flag in the
JSON), never an empty column. `rustmath-symmetricfunctions` also depends on `num-bigint`,
`num-rational`, `num-traits` (already dependencies of `rustmath-curves`); fix the sentence in 5.1.
