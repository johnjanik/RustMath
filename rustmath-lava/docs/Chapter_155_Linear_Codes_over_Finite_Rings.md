## Scope and overview

This chapter describes the Magma functions applicable to linear codes over **finite rings**.
Magma supports the basic facilities for codes over integer residue rings (`Integers(m)`) and
Galois rings (`GaloisRing(p, n)`), including cyclic codes and the complete weight enumerator
calculation. Substantial extra functionality is available for the special case of codes over
**Z₄**, the integers modulo 4 — the *quaternary* codes — including the Gray map, named code
families, derived binary codes, standard form, Plotkin-type constructions, and Lee / Euclidean
weight machinery.

**Pseudo-dimension and the Howell form.** For modules over rings with zero divisors the
modules are not free, so there is no genuine notion of dimension. In Magma each code over such
a ring nevertheless has a *unique* generator matrix corresponding to the **Howell form**; the
number of rows `k` of this unique generator matrix is called the **pseudo-dimension** of the
code. The pseudo-dimension is *not* invariant between equivalent codes, so (unlike the
dimension of a code over a finite field) it does not give structural information. The **rank**
of the generator matrix, by contrast, is always well-defined and unique (based on the Smith
form, well-defined over PIRs), but `k` may be larger than the rank.

**Cardinality terminology.** Lacking a dimension, codes over finite rings are referenced by
their cardinality: a code `C` is an `(n, M, d)` code if it has length `n`, cardinality `M`, and
minimum Hamming weight `d`. As over finite fields, "code" means a *linear* code unless stated
otherwise.

**The Gray map.** Many good non-linear binary codes arise as images of simple linear quaternary
codes under the **Gray map** φ : **Z₄** → **Z₂²** (`0 ↦ 00, 1 ↦ 01, 2 ↦ 11, 3 ↦ 10`), extended
componentwise to φ : **Z₄ⁿ** → **Z₂²ⁿ**. This is a weight- and distance-preserving map from
**Z₄ⁿ** with the Lee metric to **Z₂²ⁿ** with the Hamming metric.

General reference for **Z₄**-codes: **[Wan97]**.

## 155.2 Construction of Codes

### 155.2.1 Construction of General Linear Codes

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `LinearCode< R, n | L >` | Create a code as a subspace of the `R`-space `V = R⁽ⁿ⁾` generated by the items in list `L`. Each item of `L` is one of: (a) an element of `V`; (b) a set/sequence of elements of `V`; (c) a sequence of `n` elements of `R` (an element of `V`); (d) a set/sequence of sequences of type (c); (e) a subspace of `V`; (f) a set/sequence of subspaces of `V`. | Subspace generated by the supplied generators; reduced to Howell form. |
| `LinearCode(U)` | For `U` a subspace of `V = R⁽ⁿ⁾`: the linear code `C` corresponding to the subspace `U`. | Direct. |
| `LinearCode(A)` | For a `k × n` matrix `A` over the ring `R`: the linear code generated by the rows of `A`. The rank of `A` is **not** assumed to be `k`. | Row span. |
| `PermutationCode(u, G)` | For a finite permutation group `G` of degree `n` and a vector `u` in the `n`-dimensional space `V` over `R`: the code spanned by the vectors obtained by applying the permutations of `G` to `u`. | Span of the `G`-orbit of `u`. |

*Worked examples: H155E1 (octacode O₈ over **Z₄** via `LinearCode< >` and via `sub<RSpace>`); H155E2 (code from a matrix over `GR(4,3)` using its row space); H155E3 (`PermutationCode` from `PSL(3,2)` acting on a vector over **Z₄**).*

### 155.2.2 Construction of Simple Linear Codes

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `ZeroCode(R, n)` | The `(n, 0, n)` code over `R` consisting of only the zero codeword (minimum weight is `n` by convention). | — |
| `RepetitionCode(R, n)` | The length `n` code over `R` with minimum Hamming weight `n`, generated by the all-ones vector. | — |
| `ZeroSumCode(R, n)` | The length `n` code over `R` of all codewords `(c₁,…,cₙ)` with `Σᵢ cᵢ = 0`. | — |
| `UniverseCode(R, n)` | The length `n` code over `R` with minimum Hamming weight 1, consisting of all possible codewords (the full space). | — |
| `RandomLinearCode(R, n, k)` | For a finite ring `R` and `0 < k ≤ n`: a random linear code of length `n` over `R` with `k` generators. | Random generator matrix. |

*Worked example: H155E4 (`RepetitionCode` and `ZeroSumCode` over `Integers(9)` shown to be dual: `C1 eq Dual(C2)`).*

### 155.2.3 Construction of General Cyclic Codes

A cyclic code is one generated by all the cyclic shifts of a given codeword. Using the
correspondence `(c₀, c₁, …, cₙ) ⟷ c₀ + c₁x + ⋯ + cₙxⁿ`, the cyclic codes of length `n` over a
ring `R` are in one-to-one correspondence with the principal ideals of `R[x]/(xⁿ − 1)R[x]`.

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `CyclicCode(u)` | For `u` in the `R`-space `R⁽ⁿ⁾`: the length `n` cyclic code generated by the right cyclic shifts of `u`. | Span of cyclic shifts. |
| `CyclicCode(n, g)` | For a ring `R`, positive integer `n`, and univariate polynomial `g(x) ∈ R[x]`: the length `n` cyclic code generated by `g(x)`. | Principal ideal `(g)` in `R[x]/(xⁿ − 1)`. |
| `CyclotomicFactors(R, n)` | For a Galois ring `R` (possibly an integer residue ring with prime-power modulus) and `n` coprime to the characteristic of `R`: a factorisation of `xⁿ − 1` over `R`. The factorisation is not necessarily unique over `R`; the one returned is obtained by factoring over the residue field of `R` and then performing **Hensel lifting**. | Factor over residue field, then Hensel lift. |

*Worked examples: H155E5 (cyclic codes over **Z₄** from factors of `x⁷ − 1` and `x²³ − 1`); H155E6 (cyclic code of length 5 over `GR(4,2)` from a cyclotomic factor).*

## 155.4 Codes over **Z₄**

The ring **Z₄** is a special case with extra functionality. Error-correcting codes over **Z₄**
are often called *quaternary* codes. Key concepts are the **Lee weight** and the **Gray map**,
which maps linear codes over **Z₄** to (possibly non-linear) codes over **Z₂**.

### 155.4.1 The Gray Map

For `x ∈ Z₄` the Gray map φ : **Z₄** → **Z₂²** is `0 ↦ 00, 1 ↦ 01, 2 ↦ 11, 3 ↦ 10`, extended to
φ : **Z₄ⁿ** → **Z₂²ⁿ** by concatenating component images. The result is weight- and
distance-preserving from **Z₄ⁿ** (Lee metric) to **Z₂²ⁿ** (Hamming metric). See **[Wan97, Ch. 3]**
(note that author uses a different component order).

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `GrayMap(C)` | For a **Z₄**-linear code `C`: the Gray map φ : `C` → **F₂²ⁿ**. | As defined above. |
| `GrayMapImage(C)` | For a **Z₄**-linear code `C`: the image of `C` under the Gray map, as a *sequence* of vectors in **F₂²ⁿ** (the image may be non-linear, hence not returned as a code). | Apply φ to each codeword. |
| `HasLinearGrayMapImage(C)` | For a **Z₄**-linear code `C`: `true` iff the Gray-map image is **F₂**-linear; if so, also returns the image `B` as an **F₂**-linear code and the bijection φ : `C` → `B`. | Tests linearity of φ(`C`). |

*Worked example: H155E7 (Gray image of the octacode O₈ is the non-linear (8,256,6) Nordstrom-Robinson code; `LeeWeightDistribution` of O₈ matches the Hamming weight distribution of the image; the code K₈ has a linear Gray image).*

| `ReedMullerCodesLRMZ4(r, m)` | For `m ≥ 1` and `0 ≤ r ≤ m`: a *set* of `r`-th order Reed–Muller codes over **Z₄** of length `2ᵐ⁻¹`. | `ReedMullerCodeRMZ4(s, r, m)` | For `m ≥ 1`, `0 ≤ r ≤ m`, and `0 ≤ s ≤ ⌊(m−1)/2⌋`: an `r`-th order Reed–Muller code over **Z₄** of length `2ᵐ⁻¹`, denoted `RM_s(r, m)`. ### 155.4.3 Derived Binary Codes

Besides the Gray-map image, a quaternary code has two associated canonical binary codes: the
*residue* code and the *torsion* code, the residue being a subcode of the torsion. From any
binary code-subcode pair `C₁ ⊂ C₂`, a quaternary code `C` can be built whose residue / torsion
codes are `C₁` / `C₂` respectively (this quaternary code is not unique).

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `BinaryResidueCode(C)` | For a quaternary code `C`: the binary code formed by reducing each codeword of `C` modulo 2 (the *binary residue code*). | Reduce codewords mod 2. |
| `BinaryTorsionCode(C)` | For a quaternary code `C`: the binary code formed by the supports of the codewords of `C` that are zero modulo 2 (the *binary torsion code*). | Supports of codewords `≡ 0 (mod 2)`. |
| `Z4CodeFromBinaryChain(C1, C2)` | For binary codes `C₁ ⊂ C₂`: a quaternary code whose binary residue code is `C₁` and binary torsion code is `C₂`. | Construct a quaternary lift of the chain (non-unique). |

*Worked example: H155E12 (derived binary codes of the **Z₄** Golay code equal the binary Golay code; reconstructed quaternary code differs from the original).*

### 155.4.4 The Standard Form

A **Z₄**-linear code is in *standard form* if its generator matrix is
`[[I_{k₁}, A, B], [0, 2I_{k₂}, 2C]]`, where `I_{k₁}`, `I_{k₂}` are identity matrices, `A`, `C`
are **Z₂**-matrices, and `B` is a **Z₄**-matrix. Any **Z₄**-linear code is permutation-equivalent
to a code in standard form, and the integers `k₁`, `k₂` are unique **[Wan97, Prop. 1.1]**.

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `StandardForm(C)` | For any **Z₄**-linear code `C`: a permutation-equivalent code `S` in standard form, together with the isomorphism from `C` onto `S`. | Reduction to standard form. |

*Worked example: H155E13 (`StandardForm` of a small code; the standard code may have fewer generator-matrix rows; codeword images under the isomorphism `f`).*

### 155.4.5 Constructing New Codes from Old

These functions produce a new code over **Z₄** by modifying the codewords of given codes over **Z₄**.

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `PlotkinSum(A, B)` (matrices) | For matrices `A`, `B` over the same ring with the same number of columns: the matrix `P_AB = [[A, A], [0, B]]`. | Block matrix construction. |
| `PlotkinSum(C, D)` (codes) | For codes `C`, `D` over the same ring and of the same length: the Plotkin sum — all vectors `(u | u + v)`, `u ∈ C`, `v ∈ D`. Returns the code generated by `P_AB` where `A`, `B` are generator matrices of `C`, `D`. | Generator-matrix Plotkin sum. |
| `QuaternaryPlotkinSum(A, B)` (matrices) | For matrices `A`, `B` over **Z₄** with the same number of columns: `QP_AB = [[A, A, A, A], [0, B, 2B, 3B]]`. | Block matrix construction. |
| `QuaternaryPlotkinSum(C, D)` (codes) | For codes `C`, `D` over **Z₄** of the same length: the Quaternary Plotkin sum — all vectors `(u, u + v, u + 2v, u + 3v)`, `u ∈ C`, `v ∈ D`. | Generator-matrix `QP_AB`. |
| `BQPlotkinSum(A, B, C)` (matrices) | For matrices `A`, `B`, `C` over **Z₄** with the same number of columns: `BQP_ABC = [[A,A,A,A],[0,B',2B',3B'],[0,0,B̂,B̂],[0,0,0,C]]`, where `B'` is `B` with the twos replaced by ones in the rows of order two, and `B̂` is `B` with the rows of order two removed. | Block matrix construction. |
| `BQPlotkinSum(D, E, F)` (codes) | For codes `D`, `E`, `F` over **Z₄** of the same length: the BQ Plotkin sum — all vectors `(u, u + v', u + 2v' + v̂, u + 3v' + v̂ + z)`, with `u ∈ Gd`, `v' ∈ Ge'`, `v̂ ∈ Ĝe`, `z ∈ Gf`. **Note:** does not necessarily equal the code generated by the matrix `BQPlotkinSum` of the generator matrices (see H155E14). | Generator-matrix construction with `E'`/`Ê` adjustments. |
| `DoublePlotkinSum(A, B, C, D)` (matrices) | For matrices `A`, `B`, `C`, `D` over **Z₄** with the same number of columns: `DP_ABCD = [[A,A,A,A],[0,B,2B,3B],[0,0,C,C],[0,0,0,D]]`. | Block matrix construction. |
| `DoublePlotkinSum(E, F, G, H)` (codes) | For codes `E`, `F`, `G`, `H` over **Z₄** of the same length: all vectors `(u, u + v, u + 2v + z, u + 3v + z + t)`, `u ∈ E`, `v ∈ F`, `z ∈ G`, `t ∈ H`. Returns the code generated by `DP_ABCD` of the generator matrices. | Generator-matrix `DP_ABCD`. |
| `DualKroneckerZ4(C)` | For a code `C` over **Z₄** of length `2ᵐ`: its Kronecker dual code `C⊥_⊗ = { x ∈ Z₄^{2ᵐ} : x·K_{2ᵐ}·yᵗ = 0 ∀ y ∈ C }`, where `K_{2ᵐ} = ⊗ⱼ K₂`, `K₂ = [[1,0],[0,3]]`, `⊗` the Kronecker product. Equivalently `K_{2ᵐ}` is a quaternary matrix with `(1,3,3,1,3,1,1,3,…)` on the main diagonal and zeros elsewhere. | Kronecker-weighted orthogonality. |

*Worked examples: H155E14 (BQ Plotkin sum of matrices ≠ BQ Plotkin sum of codes); H155E15 (`PlotkinSum`/`BQPlotkinSum` of generator matrices recover `ReedMullerCodeRMZ4` codes).*

## 155.6 Weight Distributions

For a linear code, weight and distance distributions are equivalent (in particular minimum
weight equals minimum distance).

### 155.6.1 Hamming Weight

For `x ∈ R` (any finite ring) the Hamming weight is `w_H(x) = 0 ⟺ x = 0`, `w_H(x) = 1 ⟺ x ≠ 0`;
for `v ∈ Rⁿ`, `w_H(v)` is the sum (in **Z**) of the component weights. Often called simply the
*weight*.

| Intrinsic | Description |
|-----------|-------------|
| `MinimumWeight(C)` / `MinimumDistance(C)` | The minimum (Hamming) weight of the words of `C`, equal to the minimum distance between any two codewords. |
| `WeightDistribution(C)` | The (Hamming) weight distribution of `C`, as a sequence of tuples `⟨wᵢ, number of codewords of weight wᵢ⟩`. |
| `DualWeightDistribution(C)` | The (Hamming) weight distribution of the dual code of `C`. |

*Worked example: H155E18 (`WeightDistribution` of a cyclic code over the Galois ring `GR(9,2)`).*

### 155.6.2 Lee Weight

For `x ∈ Z₄` the Lee weight is `w_L(0) = 0`, `w_L(1) = w_L(3) = 1`, `w_L(2) = 2`; for `v ∈ Z₄ⁿ`,
`w_L(v)` is the sum (in **Z**) of the component Lee weights. See **[Wan97, p. 16]**.

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `LeeWeight(a)` | The Lee weight of the element `a ∈ Z₄`. | — |
| `LeeWeight(v)` | The Lee weight of the codeword `v`. | — |
| `LeeDistance(u, v)` | The Lee distance between codewords `u`, `v` of the same code `C` — the Lee weight of `u − v`. | — |
| `MinimumLeeWeight(C)` / `MinimumLeeDistance(C)` | The minimum Lee weight of `C`. | — |
| `LeeWeightDistribution(C)` | The Lee weight distribution of `C`. | — |
| `DualLeeWeightDistribution(C)` | The Lee weight distribution of the dual of `C`. | — |
| `WordsOfLeeWeight(C, w)` | The set of all words of `C` of Lee weight `w`. Parameter `Cutoff` (`RngIntElt`, default `∞`): if set to a non-negative integer `c`, terminate after `c` words found. | Enumeration. |
| `WordsOfBoundedLeeWeight(C, l, u)` | The set of all words of `C` with Lee weight between `l` and `u` inclusive. Parameter `Cutoff` (`RngIntElt`, default `∞`): terminate after `c` words found. | Enumeration. |

*Worked example: H155E19 (Lee weight distribution of `ReedMullerCodeZ4(1,3)` and enumeration of all words of Lee weight 8 via `WordsOfLeeWeight`).*

### 155.6.3 Euclidean Weight

For `x ∈ Z₄` the Euclidean weight is `w_E(0) = 0`, `w_E(1) = w_E(3) = 1`, `w_E(2) = 4`; for
`v ∈ Z₄ⁿ`, `w_E(v)` is the sum (in **Z**) of the component Euclidean weights. See **[Wan97, p. 16]**.

| Intrinsic | Description |
|-----------|-------------|
| `EuclideanWeight(a)` | The Euclidean weight of the element `a ∈ Z₄`. |
| `EuclideanWeight(v)` | The Euclidean weight of the **Z₄**-codeword `v`. |
| `EuclideanDistance(u, v)` | The Euclidean distance between **Z₄**-codewords `u`, `v` of the same code — the Euclidean weight of `u − v`. |
| `MinimumEuclideanWeight(C)` / `MinimumEuclideanDistance(C)` | The minimum Euclidean weight of the **Z₄**-code `C`. |
| `EuclideanWeightDistribution(C)` | The Euclidean weight distribution of the **Z₄**-code `C`. |
| `DualEuclideanWeightDistribution(C)` | The Euclidean weight distribution of the dual of the **Z₄**-code `C`. |

*Worked example: H155E20 (Euclidean weight distribution of `QRCodeZ4(17)`).*

## 155.7 Weight Enumerators

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `CompleteWeightEnumerator(C)` | For `C` over a finite ring `R` of cardinality `q` (elements ordered): the complete weight enumerator `W_C(X₀,…,X_{q−1}) = Σ_{v∈C} X₀^{s₀(v)} X₁^{s₁(v)} ⋯ X_{q−1}^{s_{q−1}(v)}`, where `sᵢ(v)` is the number of components of `v` equal to the `i`-th ring element. Lies in a global multivariate polynomial ring over **Z** with `q` variables (angle-bracket naming allowed). See **[Wan97, p. 9]**. | Sum over codewords. |
| `SymmetricWeightEnumerator(C)` | For a **Z₄**-code `C`: the symmetric weight enumerator `swe_C(X₀,X₁,X₂) = W_C(X₀,X₁,X₂,X₁)`. Lies in a global polynomial ring over **Z** with three variables. See **[Wan97, p. 14]**. | Substitution into `W_C`. |
| `WeightEnumerator(C)` / `HammingWeightEnumerator(C)` | For `C` over a finite ring `R`: the Hamming weight enumerator `Ham_C(X,Y) = Σ_{v∈C} X^{n−w_H(v)} Y^{w_H(v)}`. Two variables, global polynomial ring over **Z**. | Sum over codewords. |
| `LeeWeightEnumerator(C)` | For a **Z₄**-code `C`: the Lee weight enumerator `Lee_C(X,Y) = Σ_{v∈C} X^{2n−w_L(v)} Y^{w_L(v)}` (`w_L` from §155.6.2). Two variables. | Sum over codewords. |
| `EuclideanWeightEnumerator(C)` | For a **Z₄**-code `C`: the Euclidean weight enumerator `Euclidean_C(X,Y) = Σ_{v∈C} X^{4n−w_E(v)} Y^{w_E(v)}` (`w_E` from §155.6.3). Two variables. | Sum over codewords. |

*Worked examples: H155E21 (`CompleteWeightEnumerator` of a cyclic code over `GR(4,2)`); H155E22 (complete / symmetric / Hamming / Lee / Euclidean weight enumerators of the octacode O₈ with named indeterminates).*

## 155.8 Constructing New Codes from Old

These operations produce a new code by modifying the codewords of a given code.

### 155.8.1 Sum, Intersection and Dual

For these operators `C` and `D` are codes in the same `R`-space `V`.

| Intrinsic | Description |
|-----------|-------------|
| `C + D` | The (vector-space) sum of the linear codes `C` and `D` (both in the same `R`-space `V`). |
| `C meet D` | The intersection of the linear codes `C` and `D` (both in the same `R`-space `V`). |
| `Dual(C)` | The dual `D` of the linear code `C`: all codewords in `V` orthogonal to all codewords of `C`. |

*Worked example: H155E23 (sum and intersection of subcodes of a cyclic code over `GR(9,2)`: `(C1 + C2) eq C3`, `(C1 meet C3) eq C1`).*

### 155.8.2 Standard Constructions

| Intrinsic | Description |
|-----------|-------------|
| `DirectSum(C, D)` | For a length `n₁` code `C` and length `n₂` code `D` over the same ring `R`: the direct sum — all length `n₁ + n₂` vectors `u|v`, `u ∈ C`, `v ∈ D`. |
| `DirectProduct(C, D)` | For a length `n₁` code `C` and length `n₂` code `D` over the same ring `R`: the direct product of length `n₁·n₂` whose generator matrix is the Kronecker product of the basis matrices of `C` and `D`. |
| `C1 cat C2` | For codes `C1`, `C2` over the same ring `R`: the concatenation — generator matrix whose rows are each row of `A` concatenated with each row of `B` (`A`, `B` the generator matrices). |
| `ExtendCode(C)` | For a length `n` code `C`: a new code `C'` by adding one coordinate to each vector so that the sum of the extended vector's coordinates is zero. |
| `ExtendCode(C, n)` | The code `C` extended `n` times. |
| `PadCode(C, n)` | Add `n` zeros to the end of each codeword of `C`. |
| `PlotkinSum(C, D)` | For codes `C`, `D` over the same ring `R` and of the same length `n`: the Plotkin sum — all vectors `u | u + v`, `u ∈ C`, `v ∈ D`. |
| `PunctureCode(C, i)` | For a length `n` code `C` and `1 ≤ i ≤ n`: a new code `C'` by deleting the `i`-th coordinate from each codeword. |
| `PunctureCode(C, S)` | For a length `n` code `C` and a set `S = {i₁,…,i_r}` of distinct integers in `[1, n]`: a new code by deleting the components `i₁,…,i_r` from each codeword. |
| `ShortenCode(C, i)` | For a length `n` code `C` and `1 ≤ i ≤ n`: a new code from those codewords of `C` with a zero in their `i`-th component, with the `i`-th component deleted; the result has length `n − 1`. |
| `ShortenCode(C, S)` | For a length `n` code `C` and a set `S = {i₁,…,i_r}` of distinct integers in `[1, n]`: a new code from those codewords with zeros in all positions `i₁,…,i_r`, with those components deleted; the result has length `n − r`. |

*Worked examples: H155E24 (`DirectSum`, `DirectProduct`, `cat` over `GR(8,2)` and resulting lengths); H155E25 (puncturing a **Z₄** code generally reduces the minimum Lee distance by 2).*

## 155.9 Operations on Codewords

### 155.9.1 Construction of a Codeword

| Intrinsic | Description |
|-----------|-------------|
| `C ! [a₁, …, aₙ]` / `elt< C | a₁, …, aₙ >` | For a code `C` ⊆ `R⁽ⁿ⁾` and elements `a₁,…,aₙ ∈ R`: the codeword `(a₁,…,aₙ)` of `C`. It is checked that the vector lies in `C`. |
| `C ! u` | For a code `C` ⊆ `V = R⁽ⁿ⁾` and `u ∈ V`: the codeword of `C` corresponding to `u`. Fails if `u ∉ C`. |
| `C ! 0` | The zero word of `C`. |

*Worked example: H155E26 (constructing codewords of a cyclic code over `GR(16,2)` via `!` and `elt< >`; runtime errors when the vector is not in the code).*

### 155.9.2 Operations on Codewords and Vectors

| Intrinsic | Description |
|-----------|-------------|
| `u + v` | Sum of codewords `u`, `v` of the same linear code `C`. |
| `-u` | Additive inverse of the codeword `u` of `C`. |
| `u - v` | Difference of codewords `u`, `v` of the same linear code `C`. |
| `a * u` | For `a ∈ R` and codeword `u ∈ C`: the codeword `a∗u`. |
| `Weight(v)` | The Hamming weight of `v` (number of non-zero components). |
| `Distance(u, v)` | The Hamming distance between codewords `u`, `v` of the same code `C`. |
| `Support(w)` | For a word `w` of the length `n` code `C`: its support as a subset of `{1..n}` (the coordinates where `w` is non-zero). |
| `(u, v)` / `InnerProduct(u, v)` | Inner product of vectors `u`, `v` (Euclidean norm), both in the parent vector space of `C`. |
| `Coordinates(C, u)` | For a length `n` linear code `C` and codeword `u`: the coordinates of `u` with respect to `C`, as `Q = [a₁,…,a_k]` over the alphabet with `u = a₁∗C.1 + … + a_k∗C.k`. |
| `Normalize(u)` | For an element `u` of a code over `R`: the normalization of `u` — the unique `v = a·u` (scalar `a ∈ R`) whose first non-zero entry is the canonical associate in `R` of the first non-zero entry of `u` (`v` is zero if `u` is zero). |
| `Rotate(u, k)` | The vector obtained from `u` by cyclically shifting its components to the right by `k` positions. |
| `Rotate(~u, k)` | Destructively rotate `u` by `k` positions. |
| `Parent(w)` | For a word `w` of the code `C`: the ambient space `V` of `C`. |

*Worked example: H155E27 (arithmetic, `Weight`, `Support` on codewords of a cyclic code over `GR(4,4)`).*

### 155.9.3 Accessing Components of a Codeword

| Intrinsic | Description |
|-----------|-------------|
| `u[i]` | For a codeword `u` of `C` over `R`: the `i`-th component of `u` (as an element of `R`). |
| `u[i] := x;` | For `u` in a subcode `C` of the full `R`-space `V = Rⁿ`, `1 ≤ i ≤ n`, and `x ∈ R`: a vector in `V` equal to `u` with its `i`-th component redefined to be `x`. |

## 155.10 Boolean Predicates

For these operators `C` and `D` are codes (subsets/subspaces) of the same `R`-space `V`.

| Intrinsic | Description |
|-----------|-------------|
| `u in C` / `u notin C` | `true` iff the vector `u` of `V` does (resp. does not) belong to `C`. |
| `C subset D` / `C notsubset D` | `true` iff `C` is (resp. is not) a subcode of `D`. |
| `C eq D` / `C ne D` | `true` iff the codes `C` and `D` are equal (resp. not equal). |
| `IsCyclic(C)` | `true` iff the linear code `C` is a cyclic code. |
| `IsSelfDual(C)` | `true` iff `C` is self-dual, i.e. `C` equals the dual of `C`. |
| `IsSelfOrthogonal(C)` | `true` iff `C` is self-orthogonal, i.e. `C` is contained in the dual of `C`. |
| `IsProjective(C)` | `true` iff the (non-quantum) code `C` is projective. |
| `IsZero(u)` | `true` iff the codeword `u` is the zero vector. |

*Worked example: H155E28 (an `[8,7]` code K₈ over **Z₄**: `IsCyclic`, `IsSelfDual`, and `K8 eq Dual(K8)`).*
