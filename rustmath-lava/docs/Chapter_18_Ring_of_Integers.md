**Handbook part:** III — Basic Rings
**Handbook pages:** 281–327 (PDF pages 410–461)

## Scope and overview

Chapter 18 describes the operators and functions for working with the ring of rational integers **Z** in Magma. Integers are the most-used objects in the system: the ring is created automatically at start-up and a single canonical object is shared throughout any session.

**Representation.** Integers smaller than 2³⁰ = 1 073 741 824 in absolute value are "single precision" and escape the overhead of multi-precision memory management; all larger integers are stored as multi-precision objects. Multiplication uses the **Karatsuba** algorithm up to 2¹⁵ bits and the **Schönhage–Strassen FFT**-based algorithm beyond that **[AHU74, vzGG99]**. Division is reduced to multiplication (with a constant scale factor) by an asymptotically-fast algorithm, sharing the same crossover point.

**GCD.** For integers within the classical range Magma uses the **Accelerated GCD** algorithm of Weber **[Web95]** (two-integer GCD) and the **Lehmer XGCD** algorithm **[Knu97]** (extended GCD). For larger integers the **Schönhage recursive ("half-GCD") algorithm** **[Sch71]** is used, crossing over at ≈32 768 bits for GCD and ≈6 000 bits for XGCD.

**Primality.** A slight adaptation of the **Miller–Rabin** compositeness test gives a rigorous primality proof for n < 34 · 10¹³ using the witness set {2, 3, 5, 7, 11, 13, 17} **[Jae93]**. For larger integers Magma invokes **ECPP** (Elliptic Curve Primality Proving), as implemented by François Morain **[AM93]**.

**Factorisation.** The general `Factorization` function chains: Cunningham database lookup (for b^k ± 1 forms **[BtR92]**), trial division, perfect-power check, **Pollard ρ** (with Brent's improvement **[Bre80]**), **SQUFOF** (Shanks's square form), **ECM** (GMP-ECM implementation, Suyama parametrisation), and **MPQS** (Arjen Lenstra's implementation). For the hardest numbers the chapter also documents a full **Number Field Sieve (NFS)** implementation supporting naive one-shot use, process-based staged factorisation (sieve / auxiliary / linear algebra / factor), distributed sieving, CWI interoperability, and polynomial-selection tools following Montgomery–Murphy **[Mur99]**.

**Random numbers** are generated by Marsaglia's **Monster** generator with period 2^{29430} − 2^{27382} **[Mar00]**, which passes the Diehard test suite **[Mar95]**.

## 18.9 Primes and Primality Testing

A composite n is identified by a **Miller–Rabin witness** a ∈ {2,…,n−1} satisfying aʳ ≢ 1 (mod n) and aʳ·2ⁱ ≢ −1 (mod n) for i = 0,…,k−1, where n−1 = r·2^k. At least 3/4 of all a are witnesses for any composite n, so random sampling (20 bases by default) makes error probability < 4^{−20}. For n < 34·10¹³ the specific bases {2, 3, 5, 7, 11, 13, 17} suffice for a proven result **[Jae93]**. For larger n, ECPP **[AM93]** proves primality rigorously.

## 18.10 Factorization

The general `Factorization` function employs a cascade of methods:

1. **Cunningham lookup** — checks if n = b^k ± 1 for small b, k, using a database of known factors plus Aurifeuillian techniques **[BtR92]**.
2. **Trial division** — removes small prime factors (default bound 10000).
3. **Perfect power check** — reduces n to a root if it is a perfect power.
4. **Pollard ρ** with Brent's acceleration **[Bre80]** (default 8191 iterations).
5. **ECM** (GMP-ECM, Suyama parametrisation) — for factors of moderate size; smoothness bounds depend on the size of the remaining composite.
6. **MPQS** (Lenstra's implementation) — for composites ≥ 25 decimal digits, optimal for semiprimes with roughly equal-sized prime factors.
7. If MPQS is disallowed via `MPQSLimit`, ECM continues indefinitely until a factor is found.

Factorisation functions return a factorisation sequence of type `RngIntEltFact`, representing n = Π pᵢ^kᵢ with p₁ < p₂ < … < pᵣ.

## 18.14 Advanced Factorization Techniques: The Number Field Sieve

Magma provides an experimental implementation of the **Number Field Sieve (NFS)**, the asymptotically-fastest general-purpose factoring algorithm. It supports both GNFS and SNFS (differing only in polynomial selection), distributed sieving over multiple machines, and interoperability with CWI's NFS tools.

The implementation uses one linear polynomial (rational side) and one higher-degree polynomial (algebraic side). For numbers of more than 100 digits, the best-known polynomial selection methods (Montgomery–Murphy **[Mur99]**) use exactly this structure.

The NFS has four algorithmic stages: **Sieving → Auxiliary data → Linear algebra → Factorisation.**

### 18.14.1 The Magma Number Field Sieve Implementation

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `SetVerbose("NFS", v)` | Set NFS verbosity (0 = silent; 1 = basic progress + parameters; 2 = detailed; 3 = expert/developer level). | — |

### 18.14.2 Naive NFS

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `NumberFieldSieve(n, F, m1, m2)` / `NFS(n, F, m1, m2)` | One-step NFS factorisation of composite n using homogeneous bivariate polynomial F with F(m1, m2) ≡ 0 (mod n). Default parameters are conservative (large factor bases); returns a nontrivial factor of n, or 0. Not optimal for benchmarking. | Number Field Sieve (GNFS/SNFS). |

### 18.14.3 Factoring with NFS Processes

An NFS process (`NFSProc`) encapsulates n, F, m1, m2, and all algorithm parameters as settable attributes.

**NFS process attributes:** `AlgebraicFBBound`, `RationalFBBound` (factor base prime bounds), `Maximuma` (sieve interval for a), `Firstb` / `Lastb` (b range), `AlgebraicLargePrimeBound` / `RationalLargePrimeBound` (large-prime bounds), `AlgebraicError` / `RationalError` (log-sieve threshold errors), `CacheSize` (1/2/3 for small/medium/large CPU cache), `OutputFilename` (base name for data files).

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `NFSProcess(n, F, m1, m2)` | Create an NFS process object for factoring composite n with polynomial F satisfying F(m1, m2) ≡ 0 (mod n). | — |
| `NumberOfRelationsRequired(P)` | Minimum number of relations needed before proceeding to auxiliary/linear-algebra stages. | Estimate from factor base sizes. |
| `FindRelations(P)` | **Stage 1 (Sieve).** Line-by-line sieve generating smooth relations. Uses log-approximations and supports up to 2 large primes per side. Returns total full relations plus cycles found. | Classical line sieve (NFS). |
| `CreateCycleFile(P)` | **Stage 2 (Auxiliary).** Detect cycles **[LD95]** in partial relations and write cycle data file. | Cycle detection **[LD95]**. |
| `CycleCount(P)` / `CycleCount(fn)` | Count cycles in partial relations of process P or in data file fn. Useful for multi-processor bookkeeping. | Cycle detection **[LD95]**. |
| `CreateCharacterFile(P)` / `CreateCharacterFile(P, cc)` | **Stage 2 (Auxiliary).** Compute quadratic character data for relations and cycles; cc (default) or cc sets of 32 character columns. | Quadratic characters (NFS). |
| `FindDependencies(P)` | **Stage 3 (Linear algebra).** Assemble relation matrix and apply block Lanczos to find linear dependencies. | Block Lanczos. |
| `Factor(P)` / `Factor(P, k)` | **Stage 4 (Factorisation).** Extract number-field square roots and attempt factorisation from each (or the k-th) dependency. Returns a proper factor or 0. | NFS square root (algebraic). |

*Worked examples: H18E10 (listing NFS process attributes); H18E11–H18E13 (attribute choices for 70-, 80-, 87-digit numbers); H18E14 (distributed NFS over two processes).*

### 18.14.5 Distributing NFS Factorizations

Sieving is distributed by assigning unique b-value ranges (`Firstb` / `Lastb`) and output filenames to each process. After sieving, use `MergeFiles` to combine data and `CycleCount` to check sufficiency (full relations + cycles > sum of factor base sizes). The factorisation stage is distributed via `Factor(P, k)` with different k values on different processors.

### 18.14.7 Tools for Finding a Suitable Polynomial

These functions support implementation of the Montgomery–Murphy polynomial selection algorithms **[Mur99]**.

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `BaseMPolynomial(n, m, d)` | Returns the homogeneous bivariate degree-d polynomial F = Σ cᵢ Xⁱ Y^{d−i} where the cᵢ are the base-m digits of n (centred, \|cᵢ\| ≤ m/2). Satisfies F(m, 1) = n; use as NFS polynomial with m1 = m, m2 = 1. Requires d ≥ 2 and n ≥ m^d. | Base-m expansion (centred). |
| `MurphyAlphaApproximation(F, b)` | Approximation of the Murphy α value of polynomial F, using primes < b. α measures root-density advantage of F over random polynomials **[Mur99]**. Each call gives slightly different results due to random sampling at primes dividing the discriminant. | Murphy α approximation **[Mur99]**. |
| `OptimalSkewness(F)` | Optimal skewness and corresponding average log size of F **[Mur99]**. | Montgomery–Murphy polynomial analysis **[Mur99]**. |
| `BestTranslation(F, m, a)` | For polynomial F with average log size a, find a locally-optimal translation G with G(m') = F(m), minimising average log size. Returns G, m', average log size of G, optimal skewness of G. | Local descent on average log size **[Mur99]**. |
| `PolynomialSieve(F, m, J0, J1, MaxAlpha: PrimeBound := 1000)` | Search over polynomial translations G = F + j₁·x²·y^{d−2} − (|j₀| + j₁·m)·x·y^{d−1} + (j₀·m)·y^d with \|j₀\| ≤ J0, \|j₁\| ≤ J1 for those with Murphy α < MaxAlpha. Returns list of tuples `<average log size + α, skewness, α, G, m, j₀, j₁>`. | Murphy α screening **[Mur99]**. |

*Worked example: H18E15 (polynomial search for a 52-digit NFS factorisation using `BaseMPolynomial`, `OptimalSkewness`, `MurphyAlphaApproximation`, `BestTranslation`, and `NFS`).*
