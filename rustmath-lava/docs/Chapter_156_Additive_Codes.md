**Handbook part:** XXI — Coding Theory

## Scope and overview

Additive codes generalise linear codes over a finite field. Given a finite field `F` and the
space `F^(n)` of all n-tuples of `F`, an *additive code* is a subset of `F^(n)` which is a
`K`-linear subspace for some subfield `K ⊆ F`. In Magma an additive code carries both an
*alphabet* `F` and a *coefficient field* `K` (a subfield of `F`); a code is regarded as being
defined by its wordset, so the same code may be presented over different coefficient fields.

Because a code may be presented over different coefficient rings, the *dimension* `k` is defined
relative to the alphabet by `#C = (#F)^k`, which permits *fractional* dimensions. Consequently
the number of generators of an additive code does **not** equal its dimension — there are
`[F : K]` times as many generators. A length-n `K`-additive code over `F` has between zero and
`n * [F : K]` generators, and is represented as an `[n, k : k_g]` `K`-additive code (where `k_g`
is the number of generators); with a known minimum weight it is written `[n, k : k_g, d]`.

Additive codes have become important through their application to quantum error-correcting
codes (Magma's quantum package is built on this machinery), but are also of interest in their
own right. As a general rule additive and linear codes may be used interchangeably: any linear
code (type `CodeLinFld`) is also an additive code (type `CodeAdd`) using its alphabet or any
subfield as coefficient field. Since the theory of purely linear codes is more general, not all
operations are transferable.

## 156.2 Construction of Additive Codes

### 156.2.1 Construction of General Additive Codes

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `AdditiveCode< F, K, n | L >` | The `K`-additive code in `F^(n)` of length `n` generated by the elements in the list `L`, where `K ⊆ F`. Items of `L` may be: (a) an element of `F^(n)`; (b) a set/sequence of elements of `F^(n)`; (c) a sequence of `n` elements of `F` (an element of `F^(n)`); (d) a set/sequence of sequences of type (c); (e) a subcode of `F^(n)`. | Span over `K` of the given generators. |
| `AdditiveCode(G)` / `AdditiveCode(K, G)` | For a matrix `G` over a field `F` and a subfield `K ⊆ F`: the `K`-additive code over `F` generated by the rows of `G`. If no `K` is specified, the prime field of `F` is used. | Row span over `K`. |
| `AdditiveCode(K, C)` | Given a code (linear or additive) `C` over `F`, and a subfield `K ⊆ F` such that the wordset of `C` forms a `K`-linear subspace: return `C` as a `K`-additive code. Errors ("Code is not additive over given field") if the wordset is not `K`-linear. | Re-interprets the existing wordset over the new coefficient field `K`. |

*Worked examples:* H156E1 (`F2`-additive code from two `F4` vectors vs. the linear code they generate — additive code has only the sums, no scalar multiples); H156E2 (`F2`-additive code over `F8` from a random 5×4 matrix, more generators than length); H156E3 (any linear code re-expressed as an additive code over a subfield via `AdditiveCode(K, C)`); H156E4 (a `K`-additive code viewed as an `E`-additive code for `E ⊆ K`; the runtime error when the wordset is not `E`-linear).

### 156.2.2 Some Trivial Additive Codes

| Intrinsic | Description |
|-----------|-------------|
| `AdditiveZeroCode(F, K, n)` | For a field `F`, subfield `K ⊆ F` and positive integer `n`: the `[n, 0, n]` code consisting of only the zero codeword (minimum weight conventionally taken to be `n`). |
| `AdditiveRepetitionCode(F, K, n)` | The `[n, 1, n]` `K`-additive code over `F` consisting of all repeating codewords. |
| `AdditiveZeroSumCode(F, K, n)` | The `[n, n−1, 2]` `K`-additive code over `F` of all codewords `(c_1,…,c_n)` with `Σ_i c_i = 0`. |
| `AdditiveUniverseCode(F, K, n)` | The `[n, n, 1]` `K`-additive code over `F` consisting of all possible codewords. |
| `RandomAdditiveCode(F, K, n, k)` | For positive integers `n` and `k` with `0 < k ≤ n * [F : K]`: a random `K`-additive code of length `n` with `k` generators over `F`. |

*Worked example:* H156E5 (over a chain `K ⊆ F`, the zero code is contained in every length-n code and every code is contained in the universe code).

## 156.3 Invariants of an Additive Code

### 156.3.1 The Ambient Space and Alphabet

A length-n additive code has an alphabet `F` and coefficient field `K ⊆ F`; its codewords form
a `K`-linear subspace of `F^(n)`.

| Intrinsic | Description |
|-----------|-------------|
| `Alphabet(C)` / `Field(C)` | The underlying field (alphabet) of the codewords of `C`; a length-n additive code with alphabet `F` has codewords from `F^(n)`. |
| `CoefficientField(C)` | The field over which the codewords of `C` are considered linear (a subfield of the alphabet). |
| `AmbientSpace(C)` | The ambient space of `C`, i.e. the generic `R`-space `V` in which `C` is contained. |
| `Generic(C)` | For a length-n additive code `C`: the generic `[n, n, 1]` code in which `C` is contained. |

*Worked example:* H156E6 (a code represented over several coefficient fields; `Alphabet`, `CoefficientField` and `#C` under different presentations).

### 156.3.2 Basic Numerical Invariants

| Intrinsic | Description |
|-----------|-------------|
| `Length(C)` | The block length `n` of `C`. |
| `Dimension(C)` | The (rational) dimension `k` of `C`, defined by `#C = (#F)^k` where `F` is the alphabet. Not necessarily equal to the number of generators, and not necessarily integral. |
| `NumberOfGenerators(C)` / `Ngens(C)` | The number of generators of `C`. Differs from the dimension when the coefficient ring is not the alphabet. |
| `#C` | The number of codewords belonging to `C`. |
| `InformationRate(C)` | The information rate `k/n` of the `[n, k]` code `C`. |

### 156.3.3 The Code Space

| Intrinsic | Description |
|-----------|-------------|
| `GeneratorMatrix(C)` / `BasisMatrix(C)` | For an `[n, k(k_g)]` `K`-additive code `C` over `F`: the `k_g × n` matrix over `F` whose rows form a basis for `C` considered as vectors over `K`. |
| `Basis(C)` / `Generators(C)` | A basis for the `K`-additive code `C`, returned as a sequence of codewords over the alphabet of `C`, which generate the code over `K`. |
| `C . i` | For an `[n, k(k_g)]` `K`-additive code `C` and `1 ≤ i ≤ k_g`: the `i`-th element of the current basis of `C` over `K`. |

### 156.3.4 The Dual Space

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `Dual(C)` | The code dual to `C`. For an additive code, this is the nullspace with respect to the trace inner product of the coefficient field. | Trace-inner-product nullspace. |
| `ParityCheckMatrix(C)` | The parity check matrix for `C`, returned as an element of `Hom(V, U)`. | — |

## 156.4 Operations on Codewords

### 156.4.1 Construction of a Codeword

| Intrinsic | Description |
|-----------|-------------|
| `C ! [a_1, ..., a_n]` / `elt< C | a_1, ..., a_n >` | For a length-n additive code `C` with alphabet `F` and elements `a_1,…,a_n` in `F`: construct the codeword `(a_1,…,a_n)` of `C`. A check is made that the vector belongs to `C`. |
| `C ! u` | For `C` defined as a subset of `V = F^(n)` and `u ∈ V`: the codeword of `C` corresponding to `u`. Fails if `u ∉ C`. |
| `C ! 0` | The zero word of `C`. |
| `Random(C)` | A random codeword of `C`. |

### 156.4.2 Arithmetic Operations on Codewords

| Intrinsic | Description |
|-----------|-------------|
| `u + v` | Sum of codewords `u` and `v` of the same code `C`. |
| `-u` | Additive inverse of the codeword `u`. |
| `u - v` | Difference of codewords `u` and `v` of the same code `C`. |
| `a * u` | For `a` in the alphabet `F` and a codeword `u` of `C`: the codeword `a * u`. |
| `Normalize(u)` | A scalar multiple of `u` whose first non-zero entry is 1. |

### 156.4.3 Distance and Weight

| Intrinsic | Description |
|-----------|-------------|
| `Distance(u, v)` | The Hamming distance between codewords `u` and `v` of the same additive code `C`. |
| `Weight(u)` | The Hamming weight of `u`, i.e. the number of non-zero components of `u`. |

### 156.4.4 Vector Space and Related Operations

| Intrinsic | Description |
|-----------|-------------|
| `(u, v)` / `InnerProduct(u, v)` | Inner product of `u` and `v` with respect to the Euclidean norm, where `u`, `v` belong to the parent vector space of `C`. |
| `TraceInnerProduct(K, u, v)` | For `u`, `v` over a finite field `L` and a subfield `K ⊆ L`: the trace (with respect to `K`) of the inner product of `u` and `v`. |
| `Support(w)` | For a word `w` of the `[n, k]` code `C`: its support as a subset of `{1..n}` (the coordinates at which `w` is non-zero). |
| `Coordinates(C, u)` | For an `[n, k : k_g]` `K`-additive code `C` and a codeword `u`: the coordinates of `u` with respect to the current basis, as a sequence `Q = [a_1,…,a_{k_g}]` over `K` with `u = a_1*C.1 + … + a_{k_g}*C.{k_g}`. |
| `Parent(w)` | For a word `w` of `C`: the ambient space `V` of `C`. |
| `Rotate(u, k)` | The vector obtained from `u` by cyclically shifting its components to the right by `k` positions. |
| `Rotate(~u, k)` | Destructively rotate `u` by `k` positions. |
| `Trace(u, S)` / `Trace(u)` | For `u` with components in `K` and a subfield `S ⊆ K`: the vector over `S` obtained from `u` by taking the trace of each component with respect to `S`. If `S` is omitted, the prime field of `K` is used. |

### 156.4.5 Predicates for Codewords

| Intrinsic | Description |
|-----------|-------------|
| `u eq v` | `true` iff codewords `u` and `v` of the same additive code are equal. |
| `u ne v` | `true` iff codewords `u` and `v` of the same additive code are not equal. |
| `IsZero(u)` | `true` iff the codeword `u` is the zero vector. |

### 156.4.6 Accessing Components of a Codeword

| Intrinsic | Description |
|-----------|-------------|
| `u[i]` | For a codeword `u` of `C` over ring `R`: the `i`-th component of `u` (as an element of `R`). |
| `u[i] := x;` | For `u` in a subcode `C` of the full `R`-space `V = R^n`, `1 ≤ i ≤ n`, and `x ∈ R`: a vector in `V` equal to `u` with its `i`-th component redefined to `x`. |

### 156.5.2 Sum, Intersection and Dual

For these operators `C` and `D` are additive codes defined as subsets/subspaces of the same
`R`-space `F^n`.

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `C + D` | For codes of the same length, over the same alphabet, with the same coefficient ring `F`: their sum with respect to `F`. | Span of the two codes. |
| `C meet D` | The intersection of the additive codes `C` and `D`. | — |
| `Dual(C)` | The dual of `C`: for an additive code, the code generated by the nullspace of `C` relative to the trace inner product. | Trace-inner-product nullspace. |

### 156.5.3 Membership and Equality

| Intrinsic | Description |
|-----------|-------------|
| `u in C` | `true` iff the vector `u` of `V` belongs to `C` (`V` the generic space containing `C`). |
| `u notin C` | `true` iff `u` does not belong to `C`. |
| `C subset D` | `true` iff the wordset of `C` is a subset of the wordset of `D`. Either code may possibly be additive. |
| `C notsubset D` | `true` iff the wordset of `C` is not a subset of the wordset of `D`. |
| `C eq D` | `true` iff `C` and `D` have the same wordsets. |
| `C ne D` | `true` iff `C` and `D` have different wordsets. |

## 156.7 The Weight Distribution

### 156.7.1 The Minimum Weight

An adaptation of the minimum weight algorithm for linear codes (Section 152.8.1) has been
developed for additive codes by Markus Grassl and Greg White. The algorithm constructs
different equivalent generator matrices, each with pivots in different column positions (its
*information set*); the *relative rank* of a generator matrix is the size of its information set
independent of the previously constructed matrices. When enumerating all generators taken `r`
at a time, once `r` exceeds the difference between a matrix's total rank and its relative rank,
the lower bound on the minimum weight is incremented by 1. The upper bound is the minimum weight
of the enumerated codewords; the computation is complete when the bounds meet. From a user's
perspective the linear-code description in 152.8.1 is sufficient; the additive algorithm is
still new and has yet to be optimised to its full potential.

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `MinimumWeight(C: parameters)` / `MinimumDistance(C: parameters)` | The minimum weight of the words of `C` (also the minimum distance between any two codewords). Parameters: `RankLowerBound` (`RngIntElt`, default 0) sets a minimum rank on the information sets used; `MaximumTime` (`RngReSubElt`, default ∞) sets a time limit in seconds of user time after which the calculation is aborted. Setting the verbose flag `"Code"` prints progress. | Grassl–White adaptation of the linear minimum-weight algorithm (Section 152.8.1): enumerate generators `r` at a time over multiple equivalent generator matrices, tightening lower/upper bounds until they meet. |

*Worked examples:* H156E8 (verbose `MinimumWeight` of a random `GF(3)`-additive code over `GF(9)`, contrasting its efficiency with computing the full `WeightDistribution`).

### 156.7.2 The Weight Distribution

| Intrinsic | Description |
|-----------|-------------|
| `WeightDistribution(C)` | The weight distribution of `C`, returned as a sequence of tuples whose `i`-th tuple `<w_i, n_i>` gives a weight and the number of codewords of that weight. |
| `DualWeightDistribution(C)` | The weight distribution of the code dual to `C` (see `WeightDistribution`). |

### 156.7.3 The Weight Enumerator

| Intrinsic | Description |
|-----------|-------------|
| `WeightEnumerator(C)` | The (Hamming) weight enumerator `W_C(x, y) = Σ_{u∈C} x^{n−wt(u)} y^{wt(u)}` for the additive code `C`. |
| `CompleteWeightEnumerator(C)` | The complete weight enumerator `W_C(z_0,…,z_{q−1})` for `C`, where `q = #E` is the size of the alphabet `E`. With the `q` elements `ω_0,…,ω_{q−1}` (for a prime field `ω_i = i`; otherwise `ω_0 = 0`, `ω_i = α^{i−1}` for `α` primitive), and `s_i(u)` the number of components of `u` equal to `ω_i`, it is `Σ_{u∈C} z_0^{s_0(u)} … z_{q−1}^{s_{q−1}(u)}`. |
| `CompleteWeightEnumerator(C, u)` | The complete weight enumerator `W_{C+u}(z_0,…,z_{q−1})` of the coset `C + u`, where `u` is an element of the generic vector space for `C`. |

### 156.7.4 The MacWilliams Transform

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `MacWilliamsTransform(n, k, q, W)` | For a hypothetical `[n, k]` linear code over a field of cardinality `q` with weight distribution `W` (as returned by `WeightDistribution`): the weight distribution `W'` of the dual code. The transform depends only on `n`, `k`, `q`, `W` — `C` itself need not exist. If `W` is not the weight distribution of an actual code the result is meaningless (negative weights may appear). | Combinatorial MacWilliams identity on the supplied integer pairs. |

## 156.8 Families of Linear Codes

### 156.8.1 Cyclic Codes

Unlike cyclic linear codes (always generated by a single generating polynomial), cyclic
additive codes may be created using either a single generator or a sequence of generators. In
the important case of `GF(2)`-additive vectors over `GF(4)`, all cyclic codes can be described by
two generators — one taken over `GF(4)`, the other over `GF(2)` — and a special function is
provided for this construction.

| Intrinsic | Description |
|-----------|-------------|
| `AdditiveCyclicCode(v)` / `AdditiveCyclicCode(K, v)` / `AdditiveCyclicCode(Q)` / `AdditiveCyclicCode(K, Q)` | For a single vector `v` or a sequence `Q` of vectors over a finite field `F`: the `K`-additive code over `F` generated by all shifts of the inputs. `K ⊆ F`; if `K` is the prime subfield of `F` it may be omitted. |
| `AdditiveCyclicCode(n, f)` / `AdditiveCyclicCode(K, n, f)` / `AdditiveCyclicCode(n, Q)` / `AdditiveCyclicCode(K, n, Q)` | For a single polynomial `f` or sequence `Q` of polynomials over a finite field `F`: the `K`-additive code of length `n` over `F` generated by all shifts of the inputs. `K ⊆ F`; may be omitted if `K` is the prime subfield. |
| `AdditiveCyclicCode(v4, v2)` | For two vectors of equal length `n`, `v4` over `GF(4)` and `v2` over `GF(2)`: the `F2`-additive code generated by all cyclic shifts of both. For `GF(2)`-additive codes over `GF(4)`, two generators suffice for any such code. |
| `AdditiveCyclicCode(n, f4, f2)` | For two polynomials `f4` over `GF(4)` and `f2` over `GF(2)` (degrees not exceeding `n−1`): the `F2`-additive code of length `n` generated by all cyclic shifts of both. Two generators suffice for any `GF(2)`-additive code over `GF(4)`. |

### 156.8.2 Quasicyclic Codes

Quasicyclic codes generalise cyclic codes; in Magma they consist of horizontally joined cyclic
blocks.

| Intrinsic | Description |
|-----------|-------------|
| `AdditiveQuasiCyclicCode(n, Q)` / `AdditiveQuasiCyclicCode(K, n, Q)` | For an integer `n` and a sequence `Q` of polynomials over a finite field `F`: the `K`-additive quasicyclic code whose cyclic blocks are generated by the polynomials in `Q`. `K ⊆ F`; may be omitted if `K` is the prime subfield. |
| `AdditiveQuasiCyclicCode(n, Q, h)` / `AdditiveQuasiCyclicCode(K, n, Q, h)` | As above, but the cyclic blocks are stacked 2-dimensionally to height `h`. |
| `AdditiveQuasiCyclicCode(Q)` / `AdditiveQuasiCyclicCode(K, Q)` | For a sequence `Q` of vectors over a finite field `F`: the `K`-additive quasicyclic code whose cyclic blocks are generated by the vectors in `Q`. `K ⊆ F`; may be omitted if prime subfield. |
| `AdditiveQuasiCyclicCode(Q, h)` / `AdditiveQuasiCyclicCode(K, Q, h)` | As above, with the cyclic blocks stacked 2-dimensionally to height `h`. |

## 156.9 New Codes from Old

These operations produce a new code by modifying the codewords of a given code.

### 156.9.1 Standard Constructions

| Intrinsic | Description |
|-----------|-------------|
| `AugmentCode(C)` | A new additive code formed by including the all-ones vector with the words of `C`. |
| `CodeComplement(C, S)` | For a subcode `S` of `C`: a code `C'` such that `C = S + C'`. Both `C` and `S` must be over the same field. |
| `DirectSum(C, D)` | The direct sum of `C` and `D`: all vectors `u|v` with `u ∈ C`, `v ∈ D`. |
| `DirectSum(Q)` | For a sequence `Q = [C_1,…,C_r]` of codes over the same field `F`: the direct sum of the `C_i`. |
| `DirectProduct(C, D)` | For an `[n_1, k_1]` code `C` and an `[n_2, k_2]` code `D` over the same ring `R`: the direct product, of length `n_1·n_2`, whose generator matrix is the Kronecker product of the basis matrices of `C` and `D`. |
| `ExtendCode(C)` | For an `[n, k, d]` additive code `C`: a new code `C'` formed by adding the extra coordinate to each vector making the coordinate sum zero. |
| `ExtendCode(C, n)` | The code obtained by extending `C` `n` times. |
| `PadCode(C, n)` | Add `n` zeros to the end of each codeword of `C`. |
| `PlotkinSum(C1, C2)` | For `C1`, `C2` over the same alphabet: the code of all vectors `u|u+v` with `u ∈ C1`, `v ∈ C2`. Zeros are appended to reconcile length differences. |
| `PlotkinSum(C1, C2, C3: parameters)` | For `C1`, `C2`, `C3` over the same alphabet `K`: the code of all vectors `u|u+a*v|u+v+w` with `u ∈ C1`, `v ∈ C2`, `w ∈ C3`. Parameter `a` (`FldFinElt`, default −1 ⇒ a primitive element of `K`) is the multiplier. Zeros are appended to equalise codeword lengths. |
| `PunctureCode(C, i)` | For an `[n, k]` code `C` and `1 ≤ i ≤ n`: a new code `C'` formed by deleting the `i`-th coordinate from each codeword. |
| `PunctureCode(C, S)` | For an `[n, k]` code `C` and a set `S = {i_1,…,i_r}` of distinct integers in `[1, n]`: a new code formed by deleting components `i_1,…,i_r` from each codeword. |
| `ShortenCode(C, i)` | For an `[n, k]` code `C` and `1 ≤ i ≤ n`: the code formed by selecting codewords of `C` having a zero in the `i`-th component and deleting that component (resulting length `n−1`). |
| `ShortenCode(C, S)` | For an `[n, k]` code `C` and a set `S = {i_1,…,i_r}` of distinct integers in `[1, n]`: the code formed by selecting codewords with zeros in each position `i_1,…,i_r` and deleting those components (resulting length `n−r`). |

### 156.9.2 Combining Codes

| Intrinsic | Description |
|-----------|-------------|
| `C1 cat C2` | For `C1`, `C2` over the same field `K`: the concatenation `C` of `C1` and `C2`; the generators of `C` are the concatenations of the generators of `C1` and `C2`. |
| `Juxtaposition(C1, C2)` | For an `[n_1, k, d_1]` code `C1` and an `[n_2, k, d_2]` code `C2` of the same dimension over the same field `K`: an `[n_1 + n_2, k, ≥ d_1 + d_2]` code whose generator matrix is `HorizontalJoin(A, B)` (`A`, `B` the generator matrices of `C1`, `C2`). |

| Intrinsic | Description |
|-----------|-------------|
| `AutomorphismGroup(C)` | The automorphism group of the additive code `C`. Currently only available for additive codes over `GF(4)`. |
| `PermutationGroup(C)` | The subgroup of the automorphism group of `C` consisting of permutations of the coordinates. Currently only available for additive codes over `GF(4)`. |
