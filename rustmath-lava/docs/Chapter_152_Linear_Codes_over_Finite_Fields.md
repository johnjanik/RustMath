# Chapter 152 — Linear Codes over Finite Fields

**Handbook part:** XXI — Coding Theory
**Handbook pages:** 5069–5143 (PDF pages 5202–5277)

---

## Scope and overview

This chapter documents Magma's machinery for *linear* codes over finite fields. Let `K` be a
finite field and `V` the vector space of `n`-tuples over `K`. With the Hamming distance
`d(x, y) = #{ 1 ≤ i ≤ n : xᵢ ≠ yᵢ }`, a subset `C ⊆ V` is an `(n, M, d)` code (minimum
distance `d`, cardinality `M`); it is an `[n, k, d]` *linear* code when `C` is a
`k`-dimensional subspace of `V`. Throughout the chapter "code" means a linear code, and `V` is
called the *ambient space* of `C`.

Magma supports linear codes over finite fields `F_q = GF(q)`, over the integer residue rings
`Z_m = Z/mZ`, and over Galois rings `GR(pⁿ, k)`. This chapter treats only those functions that
apply over `F_q`. (Additive — i.e. only-subfield-linear — codes are covered in Chapter 156;
codes over `Z₄` and other rings appear in their own chapters.)

The highlights of the facilities are:

- Construction of codes from generator matrices, parity-check matrices and generating
  polynomials (cyclic codes), and a large library of construction families (BCH, Goppa,
  alternant, quadratic-residue, Reed–Solomon, Justesen, quasi-cyclic, etc.).
- A highly optimised minimum-weight algorithm — the embedding of low-weight information
  vectors into the code space — due to Brouwer and Zimmermann **[BFK+98]**, with cyclic /
  quasicyclic improvements and parallelism.
- Various weight enumerators and the MacWilliams transform.
- A database giving access to every best-known linear code over `GF(2)` of length up to 256,
  and large fractions of best-known codes over `GF(3)`, `GF(4)`, `GF(5)`, `GF(7)`, `GF(8)`,
  `GF(9)`.
- Algebraic-geometric codes from a curve over `F_q` (in a related chapter), decoding,
  attacks against the McEliece cryptosystem, bounds, transforms, and automorphism groups for
  codes over small fields (backtrack searches due to Leon **[Leo82, Leo97]**).

The general reference for coding theory is MacWilliams and Sloane **[MS78]**.

## 152.2 Construction of Codes

### 152.2.1 Construction of General Linear Codes

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `LinearCode< R, n \| L >` | Create the code spanned within `V = R⁽ⁿ⁾` by the items of the list `L`, where each item is one of: (a) an element of `V`; (b) a set/sequence of elements of `V`; (c) a sequence of `n` elements of `R` defining an element of `V`; (d) a set/sequence of such sequences; (e) a subspace of `V`; (f) a set/sequence of subspaces of `V`. | Subspace generation. |
| `LinearCode(U)` | For `U` a subspace of `V = R⁽ⁿ⁾`, define the linear code `C` corresponding to `U`. Constructs the `k × n` generator matrix `G` (in `R⁽ᵏ ˣ ⁿ⁾`) and the `(n−k) × n` parity-check matrix `H` (in `R⁽⁽ⁿ⁻ᵏ⁾ ˣ ⁿ⁾`). | Subspace-to-code. |
| `LinearCode(A)` | For a `k × n` matrix `A` over `R`, the linear code generated by the rows of `A`. The rank of `A` need not be `k`. | Row-space of `A`. |
| `PermutationCode(u, G)` | For a permutation group `G` of degree `n` and a vector `u` in the `n`-dimensional space `V` over `R`: the code spanned by the images of `u` under all permutations of `G`. | Orbit of `u` under `G`, then span. |

*Worked examples: H152E1 (ternary Golay code as a 6-dimensional subspace of `K⁽¹¹⁾`); H152E2
(`LinearCode` from a `KMatrixSpace` element); H152E3 (`PermutationCode` from `PSL(3,2)` of
degree 7).*

### 152.2.2 Some Trivial Linear Codes

| Intrinsic | Description |
|-----------|-------------|

| `RepetitionCode(R, n)` | The `[n, 1, n]` code generated by the all-ones vector. |
| `ZeroSumCode(R, n)` | The `[n, n−1, 2]` code over `R` of all `(c₁,…,cₙ)` with `Σᵢ cᵢ = 0`. |

### 152.2.3 Some Basic Families of Codes

Describes three important, easily-understood families used in later examples: cyclic codes,
Hamming codes and Reed–Muller codes. More cyclic-code variants and generalisations appear in
later sections.

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `CyclicCode(n, g)` | For finite field `K`, integer `n > 0`, and a univariate `g(x) ∈ K[x]` of degree `n−k` with `g(x) \| xⁿ − 1`: the `[n, k]` cyclic code generated by `g(x)`. | Generator-polynomial construction. |
| `HammingCode(K, r)` | For integer `r > 0` and finite field `K` of cardinality `q`: the `r`-th order Hamming code over `K`, of length `n = (qʳ − 1)/(q − 1)`. | Columns = projective points. |
| `SimplexCode(r)` | The `[2ʳ − 1, r, 2ʳ⁻¹]` binary simplex code, the dual of a Hamming code. | Dual of `HammingCode`. |
| `ReedMullerCode(r, m)` | For `0 ≤ r ≤ m`: the `r`-th order binary Reed–Muller code of length `n = 2ᵐ`. | Standard Reed–Muller construction. |

*Worked examples: H152E5 (length-23 binary Golay code as a `CyclicCode` from a degree-11 factor
of `x²³ − 1`); H152E6 (third-order Hamming code over `GF(2)` with its parity-check matrix);
H152E7 (first-order Reed–Muller code of length 16, orthogonal pair count).*

## 152.8 The Weight Distribution

### 152.8.1 The Minimum Weight

**Algorithm.** For a linear code minimum weight equals minimum distance. The general
minimum-weight algorithm embeds low-weight information vectors into the code space so that they
map to low-weight codewords. For `C` an `[n, k]` code with generator `G`, starting at `r = 1`
all linear combinations of `r` rows are enumerated; the minimum weight over these gives an
upper bound `d_upper`, and a strictly increasing function `d_lower(r)` bounds the
non-enumerated vectors. The algorithm terminates when `d_lower(r) ≥ d_upper`, at which point
the minimum weight equals `d_upper`. The method, for non-cyclic codes, is due to A. E. Brouwer
and K. H. Zimmermann **[BFK+98]**: construct many distinct generator matrices for the same code
with information sets as disjoint as possible, so each gives a different embedding and increases
the chance of mapping a low-weight information vector onto a low-weight codeword. The matrix's
*relative rank* is the size of its information set independent of previously constructed
matrices; once `r` exceeds the dimension minus the relative rank, `d_lower` increments by 1.
Brouwer's improvement (enumerate only one information set) applies to cyclic codes; a
generalisation by G. White covers quasicyclic codes and codes whose known automorphisms have
large cycles. Information sets are discarded if their ranks are too low to contribute.

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `MinimumWeight(C: parameters)` / `MinimumDistance(C: parameters)` | The minimum weight (= minimum distance) of `C`. Parameters: `Method` (`"Auto"` default, or `"Distribution"` / `"Zimmerman"`), `RankLowerBound` (default 0; minimum rank of information sets used), `MaximumTime` (default ∞; user-time limit after which the calculation is aborted), `Nthreads` (default 1; over `F₂`, number of POSIX threads, alternatively `SetNthreads`). | Brouwer–Zimmermann embedding **[BFK+98]**; brute-force `"Distribution"` for small codes. Verbose flag `"Code"` reports progress. |
| `MinimumWeightBounds(C)` | The currently known lower and upper bounds on the minimum weight of `C`. | — |
| `ResetMinimumWeightBounds(C)` | Undefine the known minimum weight of `C` and reset any known bounds. | — |
| `VerifyMinimumDistanceLowerBound(C, d)` / `VerifyMinimumWeightLowerBound(C, d)` | Run the minimum-weight algorithm until it determines whether `d` is a lower bound on the minimum weight of `C`. Returns: a boolean (`true` iff `d` verified as a lower bound, `false` if aborted on time); the best available lower bound; a boolean (`true` iff that value is the actual minimum weight). Parameters `RankLowerBound` (default 0), `MaximumTime` (default ∞). | Same Brouwer–Zimmermann machinery **[BFK+98]**. |
| `VerifyMinimumDistanceUpperBound(C, d)` / `VerifyMinimumWeightUpperBound(C, d)` | As above, but verifying whether `d` is an upper bound on the minimum weight. Returns a boolean, the best available upper bound, and a boolean (`true` iff actual minimum weight). Parameters `RankLowerBound` (default 0), `MaximumTime` (default ∞). | **[BFK+98]**. |
| `MinimumWord(C)` | One word of `C` having minimum weight. | **[BFK+98]**. |
| `MinimumWords(C)` | The set of all words of `C` having minimum weight. Parameters: `NumWords` (terminate after that many words found), `Method` (`"Auto"` default, or `"Distribution"` / `"Zimmerman"`), `RankLowerBound` (default ∞), `MaximumTime` (default ∞). | A variation of the Zimmermann minimum-weight algorithm; brute-force enumeration for small codes. Verbose flag `"Code"`. |
| `IncludeAutomorphism(~C, p)` / `IncludeAutomorphism(~C, G)` | Include an automorphism `p` (or group `G`) of `C` — a column permutation or a full monomial permutation — in the known-automorphisms subgroup. Automorphisms with long cycles can aid the minimum-weight calculation. | Feeds White's cyclic/quasicyclic improvement. |
| `KnownAutomorphismSubgroup(C)` | The maximally known subgroup of the full automorphism group of `C`. | — |

*Worked example: H152E19 (`BKLC(GF(2),77,34)`, `ResetMinimumWeightBounds`,
`VerifyMinimumWeightLowerBound` with verbose `"Code"` output).*

## 152.10 New Codes from Existing

The operations here produce a new code by modifying the codewords of a given code.

### 152.10.1 Standard Constructions

| Intrinsic | Description |

## 152.11 Coding Theory and Cryptography

The McEliece public-key cryptosystem's security depends on coding theory. An attack must
determine the coset leader (of known weight) from a user-defined error coset, treating the code
as a random code with no known structure. The best known attacks are a series of probabilistic
enumeration-based algorithms.

### 152.11.1 Standard Attacks

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `McEliecesAttack(C, v, e)` | The original McEliece decoding attack: random information sets are tested for being disjoint from the support of the desired error vector. Attempts to enumerate a vector of weight `e` from the error coset `v + C`. Parameters: `MaxTime` (default ∞; aborts if too long), `DirectEnumeration` (default `true`; whether to enumerate the coset directly or the larger code generated by ⟨C, v⟩). | McEliece's original information-set decoding. |
| `LeeBrickellsAttack(C, v, e, p)` | The Lee–Brickell attack: random information sets are tested for having weight ≤ `p` (optimal `p = 2` for most codes). Attempts to enumerate a vector of weight `e` from `v + C`. Parameters `MaxTime`, `DirectEnumeration` (default `true`). | Lee–Brickell information-set decoding. |
| `LeonsAttack(C, v, e, p, l)` | Leon's attack: for random information sets of size `k`, a punctured code of length `k + l` is searched for codewords of weight ≤ `p`. Optimal (small codes, length ≲ 200): `p = 2`, `l ∈ 3–6`; larger codes `p = 3`, `l ∈ 7–10`. Parameters `MaxTime`, `DirectEnumeration` (default `true`). | Leon's information-set decoding with puncturing. |
| `SternsAttack(C, v, e, p, l)` | Stern's attack: a punctured code of length `k + l` is split into two subspaces, each enumerated up to weight `p`, with collisions found at zero non-information weight. Optimal (length ≲ 500): `p = 2`, `l ∈ 9–13`; larger `p = 3`, `l` from 20 up. Parameters `MaxTime`, `DirectEnumeration` (default `true`). | Stern's collision-based decoding. |
| `CanteautChabaudsAttack(C, v, e, p, l)` | The Canteaut–Chabaud attack: like Stern's but a different linear-algebra process steps through information sets more quickly, at the cost of less independent information sets. Optimal (length ≲ 1000): `p = 1`, `l ∈ 6–9`; very large codes `p = 2`, `l` from 20 up. Parameters `MaxTime`, `DirectEnumeration` (default `true`). | Canteaut–Chabaud stepped decoding. |

### 152.11.2 Generalized Attacks

The decoding attacks can be put into a uniform two-stage framework; Magma allows any combination
of the implemented methods, including improvements.

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `DecodingAttack(C, v, e)` | A generalized decoding attack with user-specified enumeration and matrix-sequence procedures; enumerates a vector of weight `e` from `v + C`. Parameters: `Enumeration` (`"Standard"` default, `"Leon"`, `"HashTable"` — the methods of Lee–Brickell, Leon, Stern); `MatrixSequence` (`"Random"` default, or `"Stepped"`); `NumSteps` (default 1; generalised stepped process with sets differing in this many places); `p` (default 2); `l` (enumeration parameter); `MaxTime` (default ∞); `DirectEnumeration` (default `true`). For lengths 500–1000, best performance with a multiply-stepped sequence (~10 steps), hashtable enumeration, `p = 2`, `l ∈ 15–20`. | Generalised two-stage information-set decoding combining the standard attacks. |

## 152.13 Best Known Linear Codes

An `[n, k]` code `C` is a *best known linear* `[n, k]` code (BKLC) if it has the highest minimum
weight among all known `[n, k]` linear codes; it is *optimal* if its minimum weight achieves the
theoretical upper bound. Magma has databases of best-known linear codes over `GF(q)` for
`q = 2, 3, 4, 5, 7, 8, 9` (the `GF(2)` database is complete up to length 256, containing 33 152
codes; the `GF(3)` database is a contribution of Markus Grassl, etc.). The BKLC database uses
the tables of bounds compiled by A. E. Brouwer **[Bro98]** (online version **[Bro]**
discontinued; similar tables now maintained by Markus Grassl **[Gra]**).

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `BKLC(K, n, k)` / `BestKnownLinearCode(K, n, k)` | For finite field `K`, `0 ≤ k ≤ n`: an `[n, k]` linear code over `K` with the largest minimum weight among all known `[n, k]` codes. A second boolean return signals whether the desired code exists in the database. Databases over `GF(q)`, `q = 2,3,4,5,7,8,9`, lengths up to `n_max`. | Database lookup; verbose flag `BestCode` prints the construction method. |
| `BLLC(K, k, d)` / `BestLengthLinearCode(K, k, d)` | For finite field `K`, positive integers `k`, `d`: a linear code over `K` of dimension `k`, minimum weight ≥ `d` with the shortest length among known codes, plus a boolean (exists in database). | Database lookup; verbose `BestCode`. |
| `BDLC(K, n, d)` / `BestDimensionLinearCode(K, n, d)` | For finite field `K`, positive integer `n`, `d ≤ n`: a linear code over `K` of length `n`, minimum weight ≥ `d` with the largest dimension among known codes, plus a boolean. | Database lookup; verbose `BestCode`. |

*Worked examples: H152E38 (`BKLC(GF(2),23,12)` is optimal); H152E39 (`BKLC` over `GF(4)`,
checking the database-existence boolean); H152E40 (`BestLengthLinearCode` over `GF(2)`); H152E41
(`BDLC` over `GF(4)`); H152E42 (`BKLC(GF(2),54,36)` with verbose `BestCode`, then re-creating the

## 152.14 Decoding

Magma supplies functions for decoding vectors from the ambient space of a linear code `C`. The
functions in this section apply only to codes over finite fields.

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `Decode(C, v: parameters)` | Decode `v` (from the ambient space `V` of `C`) with respect to `C`. Returns `true` and the decoded `v'`, or `false` and the zero vector on failure. ## 152.16 Automorphism Groups

### 152.16.1 Introduction

For an `[n, k]` linear code `C` and a permutation group `G` of degree `n`, `G` acts on `C` by
permuting coordinate positions (the *permutation* action). For non-binary codes over a field
`K` there is also a *monomial* action: a monomial permutation of monomial degree `n` is a
permutation `s` on `K* × {1,…,n}` with `(α,i)ˢ = (β,j) ⟹ (γα,i)ˢ = (γβ,j)`; the actual degree
of `s` is `(q−1)n`. The pair `(α, i)` is numbered `(q−1)(i−1) + α`.

The algorithms in Magma for these actions are **backtrack searches due to Jeff Leon
[Leo82, Leo97]**. Four algorithms are provided for codes of length `n` over a field of
cardinality `q`:

- **Automorphism / Monomial group:** the group of monomials mapping a code into itself
  (degree `(q−1)n`); `q` any small prime or 4.
- **Permutation group:** the group of permutations mapping a code into itself (degree `n`);
  `q` any small prime or 4.
- **Equivalence test:** whether a monomial permutation maps one code to another, returning the
  monomial as a permutation of degree `(q−1)n`; `q` any small prime or 4.
- **Isomorphism test:** whether a permutation maps one code to another, returning the
  permutation of degree `n`; `q` may only be 2.

### 152.16.2 Group Actions

| Intrinsic | Description |
|-----------|-------------|
| `v ^ x` | For codeword `v` of `C` and `x` in a permutation group `G`: the vector `w` from `v` by the action of `x`. Permutation action if `G` has degree `n`; monomial action if degree `n(q−1)`. |
| `v ^ G` | For codeword `v` of `C` and a permutation group `G` (permutation or monomial action): the vector orbit `Y` of `v` under `G` (a `G`-set). |
| `C ^ x` | For code `C` and `x` in a permutation group `G`: the code of all images of the codewords of `C` under `x`. |
| `C ^ G` | For code `C` and a permutation group `G`: the orbit `Y` of `C` under `G` (a `G`-set). |
| `S ^ x` (codewords) | For a set/sequence `S` of codewords of `C` and `x` in a permutation group: the set/sequence of vectors obtained by permuting coordinates of each `v ∈ S` by `x`. |
| `S ^ x` (codes) | For a set/sequence `S` of codes of length `n` and `x` in a permutation group: the set/sequence of images of the codes under `x`. |
| `Fix(C, G)` | For an `[n, k]` code `C` and a permutation group `G` of degree `n`: the subcode of `C` of those vectors fixed by every element of `G`. |

### 152.16.3 Automorphism Group

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `AutomorphismGroup(C: parameters)` / `MonomialGroup(C: parameters)` | The automorphism group `A` of the `[n, k]` code `C` over `K`: the group of all monomial-action permutations preserving the code (degree `n(q−1)`, `q = #K`). Also returns a power structure `P` and transfer map `t` so that `f = t(g)` represents `g` as a map `P : C → C`. Parameter `Weight` (RngIntElt, default 0): specify the set of vectors of the given weight to use as the support, if the code has few low-weight words. Warning: too small a `Weight` set risks the algorithm getting stuck. | Leon backtrack search **[Leo82, Leo97]** using a set of low-weight words as invariant support. |
| `PermutationGroup(C)` | The permutation group `G` of the `[n, k]` code `C` over `K`: all permutation-action permutations preserving the code (degree `n`). Also returns a power structure `P` and transfer map `t`. | Leon backtrack search **[Leo82, Leo97]**. |
| `AutomorphismSubgroup(C)` / `MonomialSubgroup(C)` | A subgroup of the (monomial) automorphism group of `C`: the full group if already known, otherwise a subgroup generated by one element (allows finding just one automorphism). Also returns `P` and `t`. | **[Leo82, Leo97]**. |
| `AutomorphismGroupStabilizer(C, k)` / `MonomialGroupStabilizer(C, k)` | The subgroup of the (monomial) automorphism group `A` of `C` stabilizing the first `k` base points chosen by the backtrack search. Also returns `P` and `t`. | **[Leo82, Leo97]** backtrack with stabiliser. |
| `Aut(C)` | The power structure `A` of all automorphisms of `C` (monomial action), with the transfer map `t` into `A` from the generic symmetric group. | **[Leo82, Leo97]**. |
| `Aut(C, T)` | As `Aut(C)`; the string `T` (`"Monomial"` or `"Permutation"`) selects the action type. | **[Leo82, Leo97]**. |

*Worked examples: H152E45 (`AutomorphismGroup` of the second-order Reed–Muller code of length 64,
`FactoredOrder`, `CompositionFactors`); H152E46 (`AutomorphismGroup` of a BCH code using
`Weight := MinimumWeight(C)` as the invariant set).*

### 152.16.4 Equivalence and Isomorphism of Codes

| Intrinsic | Description | Algorithm |
|-----------|-------------|-----------|
| `IsIsomorphic(C, D: parameters)` / `IsEquivalent(C, D: parameters)` | For `[n, k]` codes `C`, `D`: `true` iff `C` is equivalent to `D` (with respect to the monomial action); if so, also an equivalence map `f` from `C` onto `D`. First computes none, one, or both of the automorphism groups of the two codes to assist isomorphism testing. Parameters: `AutomorphismGroups` (`Both`, `Left`, `Right` (default), `None`) selecting which automorphism groups are constructed first; `Weight` (RngIntElt, default 0) specifying the set of invariant vectors of a given weight if the algorithm gets stuck. Warning: too small a `Weight` set risks getting stuck. | Leon backtrack search **[Leo82, Leo97]**. |
